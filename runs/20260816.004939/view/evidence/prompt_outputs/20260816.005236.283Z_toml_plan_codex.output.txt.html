# ARCHITECTURE: TOML 1.0.0 Parser

| Field       | Value |
|-------------|-------|

## Questions

- None.

## Intent

The project is a Go command-line filter that parses TOML 1.0.0 from standard input and emits the required tagged JSON representation. The implementation is self-contained and uses only the Go standard library.

## Modules and Boundaries

| Module | Responsibility |
|---|---|
| `cmd/toml-decoder` | Process stdin, invoke the parser, encode successful results as JSON, and report failures. |
| `internal/toml` | Parse TOML 1.0.0 and construct tagged values and table/array structures. |

The command accepts no arguments, configuration, network access, or persistent state. Invalid input must not produce a successful stdout payload.

## Tagged Value Model

Scalar values are represented as objects with string-valued `type` and `value` fields. Tables are JSON objects and arrays are JSON arrays. Supported scalar types are `string`, `integer`, `float`, `bool`, `datetime`, `datetime-local`, `date-local`, and `time-local`.

## Technology Stack

- Go 1.22 or newer, with `go.md` governing implementation.
- Shell harnesses, with `common.md` governing supplied verification scripts.
- No third-party Go modules.

# FEATURE: Decoder Contract

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Defines the stdin, tagged-JSON, diagnostic, and exit-status contract of the decoder command. |
| Depends On  | ARCHITECTURE.md |
| Provides    | stdin TOML filter, tagged JSON output, invalid-input exit contract |
| Consumes    | internal/toml.Decode |

## Questions

- None.

## Workflow

The command reads the complete TOML document from stdin. On valid input it writes exactly one tagged JSON document to stdout and exits zero. On invalid input it writes a diagnostic to stderr, writes no successful JSON payload to stdout, and exits nonzero.

The command accepts no positional arguments or options and has no configuration or side effects.

## Tagged JSON Contract

Every scalar TOML value is encoded as:

```json
{"type":"<TOML_TYPE>","value":"<TOML_VALUE>"}
```

Integer, float, and boolean values retain their TOML spelling in the string-valued `value` field. Tables and arrays retain their object and array structure.

## Scope

The parser supports basic strings, literal strings, multiline basic strings, and multiline literal strings. It applies TOML escape rules, Unicode scalar escapes, delimiter rules, newline trimming, line-ending backslashes, and control-character restrictions.

Strings preserve their required TOML value semantics while the decoder emits them as tagged `string` values.

The parser supports lowercase booleans, signed decimal integers, hexadecimal, octal and binary integers, valid underscore placement, the signed 64-bit range, decimal and exponent floats, special values, and signed zero. Invalid numeric forms are rejected rather than coerced.
