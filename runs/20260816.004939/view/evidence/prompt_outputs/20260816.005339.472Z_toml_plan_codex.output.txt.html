# FEATURE: Parser Keys

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Parses TOML bare, quoted, and dotted keys while enforcing key-definition semantics. |
| Depends On  | ARCHITECTURE.md, FEATURE-Decoder-Contract.md, FEATURE-Parser-Strings.md, FEATURE-Parser-Lexical-Boundaries.md |
| Provides    | TOML key parsing and key-definition semantics |
| Consumes    | internal/toml.Decode |

## Questions

- None.

## Purpose

The parser accepts bare, quoted, and dotted keys, including whitespace around dotted segments and implicit table creation. It rejects duplicate definitions and attempts to extend scalar values as tables.

## Workflow

1. Read a key/value assignment from the current TOML table context.
2. Parse each bare or quoted key segment.
3. Resolve dotted segments into nested tables.
4. Reject duplicate keys and scalar/table conflicts.
5. Store the parsed value in the resulting document tree.

## Questions

- None.

## Purpose

The parser implements standard table headers, implicit parents, table redefinition rules, arrays of tables, nested arrays of tables, and most-recent-element targeting.

## Workflow

1. Parse a standard table or array-of-tables header.
2. Resolve its path through existing tables and array elements.
3. Create implicit parents where TOML permits them.
4. Select or append the correct array element.
5. Reject redefinitions, reversed parent ordering, and table/array conflicts.
6. Parse subsequent assignments into the selected table.

# FEATURE: Parser Arrays and Inline Tables

| Field       | Value |
|-------------|-------|

| Provides    | TOML arrays and inline-table parsing |
| Consumes    | internal/toml.Decode |

## Questions

- None.

## Purpose

The parser supports empty, nested, mixed, multiline, commented, and trailing-comma arrays, together with nested inline tables and dotted keys inside inline tables. Inline tables remain closed after their terminating brace.

## Workflow

1. Detect an array or inline-table value.
2. Parse nested values using the TOML value grammar.
3. Permit multiline whitespace, comments, and trailing commas in arrays.
4. Parse comma-separated inline-table entries without a trailing comma.
5. Close inline tables permanently after `}`.
6. Reject malformed delimiters and later extensions of inline tables.

# FEATURE: Parser Datetimes

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Parses TOML offset and local date/time values and emits their required tagged representations. |
| Depends On  | ARCHITECTURE.md, FEATURE-Decoder-Contract.md, FEATURE-Parser-Lexical-Boundaries.md |
| Provides    | TOML offset datetime, local datetime, local date, and local time parsing |
| Consumes    | internal/toml.Decode |

## Questions

- None.

## Purpose

The parser recognizes offset datetimes, local datetimes, local dates, and local times, including permitted separators, offsets, and fractional precision. It encodes values using the required tagged JSON representation.

## Workflow

1. Classify a scalar token as an offset datetime, local datetime, local date, or local time.
2. Validate calendar, clock, separator, offset, and fractional-second syntax.
3. Truncate unsupported fractional precision rather than rounding.
4. Emit offset datetimes as RFC 3339 values.
5. Emit local values without unrelated offset or date components.
6. Reject malformed and invalid local date/time forms.
