# ARCHITECTURE: TOML Parser

| Field       | Value |
|-------------|-------|
| Version     | 20260815 V1 |

| Depends On  | — |
| Provides    | Go module, cmd/toml-decoder build entry point, internal/toml parser boundary |
| Consumes    | — |

## Questions

- None.

## Intent

The application is a command-line filter that reads one UTF-8 TOML document from standard input and emits a tagged JSON document. Parsing is owned by `internal/toml`; the fixed executable entry point is `cmd/toml-decoder`.

## Module Boundaries

| Module | Responsibility |
|---|---|
| `cmd/toml-decoder` | Read stdin, invoke the parser, encode tagged JSON, report errors, and set exit status. |
| `internal/toml` | Lex and parse TOML v1.0.0 into the tagged document model. |
| `sources/` | Supplied conformance and acceptance harness assets; read-only during implementation. |

The command must not contain TOML grammar logic. The parser must not depend on command-line arguments, configuration, network access, or third-party packages.

## Tagged Document Model

Tables are JSON objects and arrays are JSON arrays. Every scalar TOML value is represented as an object with string fields:

- `type`: one of `string`, `integer`, `float`, `bool`, `datetime`, `datetime-local`, `date-local`, or `time-local`.
- `value`: the TOML value represented as a JSON string.

## Technology Stack

- Go 1.22 or newer, using only the standard library.
- POSIX shell for supplied acceptance and conformance scripts.

## Build and Runtime Constraints

The module must compile with no `require` dependencies in `go.mod`. The executable reads only stdin, writes successful JSON only to stdout, writes diagnostics only to stderr, and exits non-zero for malformed TOML.

# FEATURE: Decoder Contract

| Field       | Value |
|-------------|-------|
| Version     | 20260815 V1 |
| Description | Defines the stdin, tagged-JSON, diagnostic, and exit-status contract for the decoder. |
| Depends On  | ARCHITECTURE.md |
| Provides    | stdin TOML decoder, tagged JSON output, invalid-input diagnostics |
| Consumes    | Go module, cmd/toml-decoder build entry point, internal/toml parser boundary |

## Questions

- None.

## Workflow

The executable reads exactly one TOML document from standard input. For valid input it parses through `internal/toml` and emits one JSON document on stdout with no diagnostic output. For invalid input it emits a diagnostic on stderr, emits no JSON document on stdout, and exits non-zero. It accepts no arguments and performs no side effects.

## Output Contract

- Tables become JSON objects.
- Arrays become JSON arrays.
- Scalar values become `{"type": "<TOML_TYPE>", "value": "<TOML_VALUE>"}`.
- Scalar `value` fields are JSON strings, including integers, floats, and booleans.
- Offset datetimes use RFC 3339 representation; local date/time values use their corresponding local representations.

| Provides    | TOML basic, literal, multiline-basic, and multiline-literal string values |
| Consumes    | stdin TOML decoder, tagged JSON output |

## Questions

- None.

## Behavior

The parser accepts all TOML v1.0.0 string forms and preserves their specified contents. Basic strings decode the permitted escape sequences and reject invalid escapes or invalid Unicode scalar values. Literal strings preserve backslashes without escape processing. Multiline strings support newline trimming, line-ending backslashes, embedded quotation rules, and the control-character restrictions defined by TOML v1.0.0.
