# FEATURE: Parser Keys

| Depends On  | FEATURE-Parser-Lexical-Boundaries.md |
| Provides    | bare keys, quoted keys, dotted keys, nested document paths, duplicate-key rejection |
| Consumes    | stdin TOML decoder, TOML lexical parsers |

## Questions

- None.

## Purpose

Support TOML key forms and map key/value assignments into nested JSON objects.

## Behavior

- Accept bare keys containing ASCII letters, digits, underscores, and dashes.
- Accept basic-string and literal-string quoted keys, including empty quoted keys.
- Accept dotted keys with whitespace around components.
- Create implicit tables for dotted paths.
- Treat quoted and bare spellings of the same key as equivalent.
- Reject duplicate keys and attempts to extend scalar or inline-table values as tables.
- Preserve numeric-looking bare keys as string keys.

## Questions

- None.

## Purpose

Support table headers and arrays of tables while preserving TOML ordering and redefinition semantics.

## Behavior

- Parse standard table headers with bare, quoted, and dotted names.
- Create implicit parent tables where permitted.
- Reject duplicate table definitions and table/scalar conflicts.
- Parse arrays of tables and append elements in source order.
- Target the most recently defined array element for nested tables and arrays.
- Reject child definitions whose array parent has not yet been established.
- Reject attempts to append to ordinary arrays or redefine tables as arrays.

## Questions

- None.

## Purpose

Recognize TOML v1.0.0 date and time forms and serialize them using the decoder's required tagged JSON representation.

## Behavior

- Parse RFC 3339 offset datetimes with `Z` and numeric offsets.
- Parse local datetimes without an offset.
- Parse local dates and local times.

- Reject malformed dates, times, offsets, and invalid local forms.
