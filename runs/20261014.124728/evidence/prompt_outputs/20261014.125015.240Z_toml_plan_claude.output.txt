# ARCHITECTURE: TOML Decoder

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Module layout, package boundaries, and technology stack for a standard-library TOML v1.0.0 decoder. |
| Depends On  | None |
| Provides    | cmd/toml-decoder, internal/toml |
| Consumes    | None |

## Questions

- None.

## Purpose

A command-line filter. It reads a TOML document on stdin, decodes it with a hand-written parser in `internal/toml`, and writes tagged JSON to stdout. Invalid input produces a diagnostic on stderr and a non-zero exit. The program takes no arguments, reads no configuration, and has no side effects.

## Modules

| Path | Responsibility |
|---|---|
| `go.mod` | Module `github.com/owner/toml-decoder`. Declares no `require` directives. Go 1.22 or newer. |
| `cmd/toml-decoder` | `package main`. Reads stdin, calls `internal/toml`, encodes the result to stdout, and writes errors to stderr. |
| `internal/toml` | Hand-written TOML v1.0.0 lexer, parser, and tagged-value model. Not importable outside the module. |

## Technology Stack

- Go, standard library only. Imports limited to `encoding/json`, `strconv`, `strings`, `unicode`, `unicode/utf8`, `time`, `math`, `fmt`, `io`, `os`, `errors`.
- No third-party TOML module, including `BurntSushi/toml`, `pelletier/go-toml`, and `naoina/toml`.
- The conformance harness is shell and Go tooling staged under `sources/`. It is scoring instrumentation, not part of the deliverable.

## Module Ownership

| Boundary | Owner | May access |
|---|---|---|
| stdin, stdout, stderr, exit status | `cmd/toml-decoder` | `os`, `io`, `encoding/json` |
| TOML syntax and semantics | `internal/toml` | `strings`, `strconv`, `unicode`, `unicode/utf8`, `time`, `math` |
| Persistence, configuration, external services | None | Not applicable |

# FEATURE: Decoder Contract

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Stdin-to-tagged-JSON contract, diagnostic stream, and exit status of the decoder command. |
| Depends On  | ARCHITECTURE.md, FEATURE-Parser-Keys.md, FEATURE-Parser-Lexical-Scalars.md, FEATURE-Parser-Arrays-Inline.md |
| Provides    | toml-decoder stdin/stdout filter contract |
| Consumes    | toml.Decode |

## Questions

- None.

## Purpose

The decoder reads TOML from stdin and writes tagged JSON to stdout with exit status 0. On invalid TOML it writes a diagnostic to stderr, writes nothing to stdout, and exits non-zero. It takes no arguments and reads no configuration.

## Tagged JSON Encoding

- Tables encode as JSON objects. Empty tables encode as `{}`.
- Arrays encode as JSON arrays. Empty arrays encode as `[]`.
- Every value encodes as `{"type": "<TYPE>", "value": "<VALUE>"}`, with `value` always a JSON string.
- `type` is one of `string`, `integer`, `float`, `bool`, `datetime`, `datetime-local`, `date-local`, `time-local`.

# FEATURE: Parser Strings

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Decoding of the four TOML string forms: basic, multi-line basic, literal, and multi-line literal. |
| Depends On  | ARCHITECTURE.md |
| Provides    | string value decoding in internal/toml |
| Consumes    | None |

## Questions

- None.

## Purpose

Decode basic strings with the listed escapes only, multi-line basic strings with newline trimming and the line-ending backslash rule, literal strings with no escaping, and multi-line literal strings. Reject any other backslash escape and any control character not permitted by the specification.

- None.

## Purpose

Decode booleans, decimal and prefixed integers (`0x`, `0o`, `0b`) with underscores, and floats with fractional and exponent parts, plus the special floats `inf`, `nan`, and their signed forms. Integers must fit signed 64-bit and are rejected otherwise.

## Purpose

A hash begins a comment that runs to end of line, except inside a string. Control characters other than tab are rejected in comments and literal strings. Input that is not valid UTF-8 is rejected.
