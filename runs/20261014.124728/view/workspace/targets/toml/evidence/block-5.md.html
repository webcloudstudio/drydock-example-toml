  • Bare, quoted, and dotted keys are parsed in a new internal/toml/keys.go. Dotted keys build nested tables, and spaces around dots are ignored.
  • Redefinition is rejected for bare, quoted, and dotted keys alike, and a key holding a value cannot later be used as a table.
  • Go tests pass under go vet and go test -race -cover, and gofmt -l is clean. The coverage is 96.3% for internal/toml and 57.1% for cmd/toml-decoder.

Why the suite gate is not a real pass

  • sources/stage_test.sh "valid/key/**|invalid/key/**" exits 0, but toml-test reports valid tests: 0 passed, 0 failed. The runner separates patterns with commas, not |, so nothing ran.
  • I ran the same gate with "valid/key/*,invalid/key/*". Results: valid 18 passed and 10 failed; invalid 61 passed and 0 failed.
  • All 10 valid failures stop at a [table] or [[array]] header (for example valid/key/alphanum at [2018_10]). Table headers are outside this story. I spot-checked the key lines before those headers and their decoded values are correct.

Choices I made

  • Internal nested tables use a separate type from tagged leaves, so a table is never mistaken for a value.
