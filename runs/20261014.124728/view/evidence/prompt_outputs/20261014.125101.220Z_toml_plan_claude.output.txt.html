# FEATURE: Parser Keys

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Bare, quoted, and dotted key forms, and the key-definition rules that reject redefinition. |
| Depends On  | ARCHITECTURE.md, FEATURE-Parser-Strings.md, FEATURE-Parser-Lexical-Scalars.md |
| Provides    | bare, quoted, and dotted key parsing with redefinition checks |
| Consumes    | None |

## Questions

- None.

## Purpose

Parse bare keys (`A-Za-z0-9_-`), quoted keys (basic or literal strings), and dotted keys that create intermediate tables. Reject defining the same key twice. A bare key and a quoted key with the same name are equivalent. A key that holds an integer cannot later be used as a table.

## Programmatic Acceptance

# FEATURE: Parser Tables

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Standard table headers, implicit super-tables, arrays of tables, and their redefinition and ordering rules. |
| Depends On  | ARCHITECTURE.md, FEATURE-Parser-Keys.md |
| Provides    | table headers and arrays of tables in internal/toml |
| Consumes    | None |

## Questions

- None.

## Purpose

Parse `[table]` headers and `[[array]]` headers. Create implicit super-tables for `[a.b.c]`. Each `[[name]]` header appends a new table element to the array named `name`, and later sub-tables attach to the most recent element. Reject a standard table defined twice, and reject a `[[name]]` header that conflicts with a static table or static array.

## Programmatic Acceptance
