# FEATURE: Parser Keys

| Field       | Value |
|-------------|-------|
| Version     | 20261021 V1 |
| Description | Parse TOML key forms and enforce key-definition uniqueness. |
| Depends On  | FEATURE-Decoder-Contract.md, FEATURE-Parser-Strings.md, FEATURE-Parser-Lexical-Scalars.md, FEATURE-Parser-Lexical-Boundaries.md |
| Provides    | TOML bare, quoted, dotted, and numeric-looking key parsing |
| Consumes    | stdin TOML decoder, TOML string parsing, TOML scalar parsing |

## Questions

- None.

## Purpose

Implement TOML v1.0.0 bare, quoted, dotted, empty quoted, and numeric-looking keys. Construct nested tables for dotted keys while preserving quoted key spelling and rejecting duplicate or conflicting definitions.

## Behavior

- Bare keys contain only ASCII letters, digits, underscores, and dashes.
- Quoted keys use basic or literal string syntax and may contain broader Unicode content.
- Dotted keys create nested tables and ignore whitespace around separators.
- Numeric-looking bare keys remain string keys.
- Equivalent key spellings cannot define the same key more than once.
- A value cannot later be reinterpreted as a table.

| Depends On  | FEATURE-Parser-Keys.md |

| Consumes    | TOML key parsing, TOML scalar parsing |

## Questions

- None.

## Purpose

Implement standard tables, implicit parent tables, arrays of tables, nested array elements, and TOML table conflict rules.

## Behavior

- Table headers create the selected table and implicit parents.
- A table cannot be defined more than once.
- Arrays of tables append elements in source order.
- Nested tables and arrays resolve against the most recently defined array element.
- Static arrays and incompatible table forms cannot be converted into tables or arrays of tables.
- Parent arrays must exist before child tables or child arrays are declared.

| Consumes    | TOML key parsing, TOML scalar parsing |

## Questions

- None.

## Purpose

Implement TOML v1.0.0 offset datetime, local datetime, local date, and local time values with tagged JSON representations and required precision handling.

## Behavior

- Offset datetimes accept RFC 3339 forms with `T` or space separators.
- Local datetimes omit the offset and retain local semantics.
- Local dates and local times receive their distinct tagged types.
- Fractional seconds beyond supported precision are truncated rather than rounded.
- Invalid calendar dates, clock values, offsets, and malformed fractional forms are rejected.
- Tagged values use `datetime`, `datetime-local`, `date-local`, and `time-local`.
